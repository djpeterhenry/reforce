# Black-box probes

Our own G-Force configs, used to measure undocumented G-Force behavior by **running G-Force normally**
and taking screenshots. No decompiling (EULA §2). See docs/architecture.md §7.

- `FlowField/`, `WaveShape/`, `ColorMap/`: probe configs (`zz reforce *`). Each file's header comment explains
  what it measures and how to read the result.
- `timelines/runN.py`: G-Force script timelines. The one chosen by `PROBE_TIMELINE` (default `run2`) is installed as
  `Scripts/Key 5.py` and runs on Shift+R then 5. Set `PROBE_SECONDS` to the timeline length plus a margin (run1: 85).
- `install.sh`: `sudo probes/install.sh` once (creates empty user-owned folders). `--remove` takes the probes out
  again, and `sudo probes/install.sh --purge` returns the G-Force install to stock.
- `run.sh [--auto]`: backs up G-Force prefs, installs the probes, runs the timeline, saves screenshots to `captures/`
  (git-ignored: G-Force output stays local), then restores the prefs and **removes the probes**. Normal G-Force use
  is unaffected between runs.

Results go into docs/scene-format.md §10 and docs/probe-results.md.

## Audio probes (Phase 5C)

Test signals go to the silent Loopback device `reforce probe`, which G-Force reads as its input during the run.

- `audio/*.json`: schedules of the generated test signals (`python3 -I tools/audio_signals/gen_signals.py`
  writes the git-ignored WAVs next to them). Every file starts with a 2 kHz sync click at 0.5 s; content
  starts at 2.0 s.
- Configs (generated by `python3 -I tools/parity/audio_layout.py --write`; geometry documented there):
  `FlowField/zz reforce strip` (top region scrolls left 1 px/frame at 1980 px, bottom region void),
  `WaveShape/zz reforce strip` (one dot per signal at the right edge: time base, LEVEL, BASS, ENERGY,
  fft(.05/.2/.5/.8), mag(.5), each in its own band with two rails; plus fft(s)/mag(s) snapshot curves at the
  bottom), `WaveShape/zz reforce spectrum` (full-screen fft(s)/mag(s) curves; use with `zz reforce void`).
  G-Force's 1/255-per-frame decay limits one screenshot to ~250 frames (~4 s), so timelines shoot every 3 s.
- Timelines `run7`…`run14` carry a `# reforce-audio: <file>.wav delay=D seconds=S` header; `run.sh` then plays
  that file D s after the scripted keypress (needs `--auto`), sets `Audio.InputSource = "reforce probe"` and
  `Audio.AutoDetect.Enabled = 0` for the run, and stops the player on exit:

      cmake --build build --target reforce-audio-play
      build/reforce-audio-play --device "reforce probe" --route-test probes/audio/test_click.wav   # route check
      PROBE_TIMELINE=run7 probes/run.sh --auto

  run7 tone steps, run8 sweep, run9 noise bands, run10 kick, run11 attack/release, run12 silence (strip
  charts); run13 sweep, run14 noise bands (full-screen spectrum snapshots every 0.5 s); follow-up: run15/run16
  `tone_freqs` (strip / spectrum), run23 `tone_pairs` (spectrum) — docs/audio-probe-results.md §9.
- Decode: `python3 -I tools/parity/audio_measure.py gforce --run run7 --captures probes/captures/<stamp>`;
  reforce side: `audio_measure.py reforce`; report: `python3 -I tools/parity/audio_compare.py` →
  docs/audio-parity.md.

## Corpus sweeps (Phase 5B.4)

Every FlowField (352) and ColorMap (37 .txt + 212 PNG strips) of the corpus, in G-Force and in reforce:

    python3 -I tools/sweep/make_timelines.py --reforce <reforce binary>   # classify, derive, write sweep_*.py
    tools/sweep/run_gforce_sweeps.sh            # G-Force, screen unlocked: 5 runs, ~20 min (DRY_RUN=1 to check)
    python3 -I tools/sweep/render_reforce.py --reforce <reforce binary>   # reforce replay (~1 min)
    python3 -I tools/sweep/compare.py           # -> docs/sweep.md + build/sweep/gallery/index.html (local)
    python3 -I tools/sweep/validate.py --reforce <reforce binary>         # kit self-test, reforce vs reforce

- `WaveShape/zz reforce sweep grid`: fixed pattern at Pen .4 (intensity 102) redrawn every frame; with the 1/255
  per-frame decay the image is exactly at its steady state 102 frames after a field starts, so shots don't depend
  on timing. `WaveShape/zz reforce sweep ramp`: 256 dots with Pen = k/255 (palette readout on the void field).
- Timelines `sweep_ff_01`…`04` (88 fields each, 2.5 s per field) and `sweep_cm_01` (0.8 s per ColorMap) carry a
  `# reforce-sweep: kind=… slots=N seconds=S` header; timing rationale in `tools/sweep/make_timelines.py`.
- Configs whose A vars use `rnd()` run as local derived copies `zz sweep <name>` (fixed K·x instead of rnd(x),
  generated into build/sweep/derived/, staged into `probes/<Type>/zz sweep/` only while the runner runs; never
  committed). `reforce --describe-config PATH…` gives the static rnd/t/audio classification.

## Phase 5B / 5F.6 probes (runs 17-22)

    PROBE_TIMELINE=run17 PROBE_SECONDS=50 probes/run.sh --auto     # FlowField morph strip (parity #30)
    PROBE_TIMELINE=run18 PROBE_SECONDS=24 probes/run.sh --auto     # dense particle strip (#31)
    PROBE_TIMELINE=run19 PROBE_SECONDS=10 probes/run.sh --auto     # sub-pixel lines and dots (#32)
    PROBE_TIMELINE=run20 PROBE_SECONDS=10 PROBE_PREFS='ColorMap.MapFunction="i^2.1"' probes/run.sh --auto   # (#33)

- run17/18 use `FlowField/zz reforce morph a|b` (scroll left 1 px per frame; b also moves the region y <= .3 down
  4 px per frame) and the clock WaveShapes `zz reforce morph strip` / `... strip 2` (time band, B0 band, morph dot);
  decoders in `tools/parity/strip5b.py`, measurements in `tools/parity/parity5b.py`.
- `run.sh` sets `ColorMap.MapFunction = "i"` first, so `PROBE_PREFS` can override it (run20).
- Movie sprites (run21, run22 diagnostic): G-Force does **not** play movies from `G-Force.ExternalSprites.Path`
  (images there work). They need the Sprite package: `sudo probes/install.sh` once more (now also creates the
  user-owned `G-Force.Sprite.package/zz reforce probes`), then
  `PROBE_SPRITE_DIR=build/probe-movies PROBE_TIMELINE=run21 PROBE_SECONDS=47 probes/run.sh --auto`
  (movies from `build/reforce-gen-videos "build/probe-movies/zz reforce movie a.mov" --size 640x360 --fps 30
  --frames 150 --pattern card` and `"... movie b.mp4" --size 480x360 --fps 24 --frames 72 --pattern card`).

## F6 line width vs frame size (run 24)

    tools/parity/resize_gforce.sh & PROBE_TIMELINE=run24 PROBE_SECONDS=62 probes/run.sh --auto
    RESIZE_SIZES="1728 1076;1500 1000;..." tools/parity/resize_gforce.sh & PROBE_TIMELINE=run24 PROBE_SECONDS=62 probes/run.sh --auto

- `WaveShape/zz reforce widths`: horizontal lines LWdt 2/5/10, vertical LWdt 5/10 (void field). A shot every 5 s; the
  resizer (System Events, needs Accessibility) watches the capture folder and resizes the window after each shot, then
  run24 goes full screen. Measured by `tools/parity/linewidth.py` (parity #38).
- **G-Force remembers the window rect it had when full screen was last entered, outside the SoundSpectrum prefs**
  (run.sh's restore does not cover it): a run that enters full screen at a resized window makes G-Force reopen at that
  size. The resizer therefore puts the window back to its shot-1 rect before run24's full-screen step. If that ever
  goes wrong: run `probes/timelines/run24_restore.py` (toggles full screen at 0:10) while setting the window back to
  Peter's rect (738,144 990x658 pt frame) via System Events before 0:10, then check the next launch.


## Sprite layering (run 26)

    python3 -I tools/parity/make_sprite26.py      # build/probe-sprites26: banded test sprite + Pen/EPen params
    PROBE_TIMELINE=run26 PROBE_SECONDS=58 \
      PROBE_PREFS='Sprite.Transition.Duration=2;Sprite.Transition.Duration.Deviation=0' \
      PROBE_GLOBAL_PREFS="G-Force.ExternalSprites.Path=\"$PWD/build/probe-sprites26\"" probes/run.sh --auto

The grid WaveShape stays on (redrawn every frame), so the 1/255-per-frame decay can't fake a sprite effect the way it
did in runs 5 and 25. Results: docs/probe-results.md #40.
