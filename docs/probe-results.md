# Black-box probe results

Measured by running G-Force 5.9.7 (Standalone, macOS) on our own probe configs (`probes/`) and analyzing the pixels of
G-Force's own `TakeScreenshot()` output (1980×1260). ColorMap `zz reforce gray` was used with `ColorMap.MapFunction = "i"`,
so pixel value = internal intensity × 255. Captures are kept locally in `probes/captures/` (not committed).

`Graphics.TargetFrameRate = 30`). Run 4: 13:21 (12 screenshots, 60 fps). Run 5: 14:02 (10 screenshots; our own test sprite via
`G-Force.ExternalSprites.Path`). Run 6: full screen via `SetFullscreen` for line width at 2234 px. Transition functions were Peter's prefs: CM `1-(1-t)^1.5`,

## Consequences for reforce
- Expression precedence: unary minus > `^` (left-assoc) > `* / %` > `+ -` > comparisons > logic.
- Tier evaluation: WaveShape C/X/Y/Pen/LWdt state is **one slot per s step**, persisting across frames (VectorC).
- Flow pass: sample the previous frame at the source point, subtract **1/255 per G-Force frame**, out-of-frame → 0.
  G-Force's decay is per frame, so to look like G-Force at its default 60 fps whatever our refresh rate, decay at
  **60/255 per second**: either step the simulation at a fixed 60 Hz, or scale the per-frame decay by dt·60, which
  needs >8-bit storage at refresh rates above 60.
- `gforce` blend modes: ColorMap = RGB lerp; FlowField = linear source-point lerp; WaveShape = per-index lerp, with unmatched
  paths dilated by `1 + 15.5·u^4.16`. All weighted by the type's `Transition.Function`.
- Line pass: draw paths in order with **overwrite** (no max/additive), Pen 0 erases; width = LWdt × s(W, H) px (#38).
  G-Force snaps points to whole pixels and covers pixels by major-axis spans (#32): `reforce.ThinLines = gforce`.
- Transitions and particle/sprite envelopes are timed in **seconds** (#30, #31), not frames: no fps emulation needed.
  WaveShape `t` is config-local (#37); reforce does the same since 5B.9 (each WaveShape's t = seconds since it loaded; A vars see t = 0).
